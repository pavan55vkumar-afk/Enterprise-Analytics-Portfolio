# Data Quality Audit & Profiling

## Business Context

An operations and billing system feeding executive dashboard reports was suspected of having data discrepancies. Before the reports could be trusted for billing reviews, leadership needed a systematic audit of the underlying transaction logs to identify missing values, duplicate entries, invalid formatting, and statistical outliers.

## Business Questions

1. Which fields in our billing transactions suffer from completeness issues (null or empty values)?
2. What is the duplicate rate of our transactions, and are there duplicate transaction IDs?
3. What percentage of our transaction attributes conform to business rules (valid email format, valid state codes, reasonable amounts)?
4. What is the impact of transaction anomalies, and what data governance steps should we implement to prevent future leakage?

## Dataset

- 1,025 synthetic billing transaction logs (1,000 base transactions and 25 deliberate duplicate rows).
- Fields: `transaction_id`, `customer_id`, `customer_email`, `transaction_date`, `transaction_amount`, `payment_method`, and `billing_state`.

*Note: All data is synthetic, generated by the included script for portfolio practice only.*

## My Approach

1. **Completeness Profiling**: Counted missing (null, empty, or whitespace) values in each column relative to total records.
2. **Uniqueness Profiling**: Checked for duplicate `transaction_id` records that should be unique primary keys.
3. **Validity Profiling**: Tested each field against defined domain business rules:
   - Emails must contain `@` and a valid domain ending.
   - Payment methods must strictly match standard values (`Credit Card`, `Debit Card`, `UPI`, `Net Banking`).
   - Billing states must match valid state codes (`NY`, `CA`, `TX`, `WA`, `FL`, `IL`, `MA`).
   - Transaction amounts must be positive and fall below a threshold of INR 10,000 (with IQR outlier check).
4. **Outlier Detection**: Identified extreme outliers and negative values in transaction amounts.
5. **Remediation Strategy**: Structured process improvements to resolve issues at the collection point.

## KPIs

- Completeness Score (% non-null)
- Uniqueness Score (% unique keys)
- Validity Score (% conforming to format rules)
- Total anomalous record counts

## Findings

- **Total Rows Audited**: 1,025
- **Unique Transactions**: 1,000 (25 duplicate rows detected, yielding a 97.56% uniqueness rate on keys)
- **Completeness Metrics**:
  - Missing Emails: **42 records** (95.90% completeness)
  - Missing Amounts: **25 records** (97.56% completeness)
  - Missing States: **12 records** (98.83% completeness)
- **Validity & Format Violations**:
  - Inconsistent Payment Method casing/labels: **74 records** (92.78% validity rate)
  - Invalid Email formats: **29 records** (97.17% validity rate)
  - Out-of-bounds State codes: **16 records** (98.44% validity rate)
  - Transaction Amount violations (Negative/Extreme Outliers): **26 records** (97.46% validity rate)

## Recommendation

- **Implement Input Field Validation**: Restrict frontend inputs on payment methods to a drop-down select element to eliminate casing variations (e.g. `cc` vs `Credit Card`).
- **Enforce Database Schema Integrity**: Set `NOT NULL` constraints on critical fields like `customer_email` and `transaction_amount`, and add a unique primary key constraint on `transaction_id` to block duplicate uploads.
- **Set Up Real-time Data Quality Checks**: Schedule a nightly SQL profiling script that alerts data engineers when any completeness or validity score drops below 99%.
- **Outlier Cleaning**: Quarantining transactions with negative amounts or amounts exceeding 3x the Interquartile Range (IQR) for manual verification before sending to financial dashboards.

## Outcome

This audit provided a clear quantification of the database's structural data issues, laying out the groundwork for engineering updates that will restore report credibility.
